# 协议与能力兼容

接入单元是具体部署。同一权重经不同引擎、模板和量化部署后，不应假定能力相同。

## 上游契约

登记协议族及版本、认证、模型 ID、凭证引用、TLS 信任、网络可达性、超时、限制、错误形式、usage 口径与责任人。公开仓库仅保留脱敏标识。

MaaS 自定义请求外壳、签名和错误码由独立适配器处理。内部 CA 应正确配置信任链，不能用关闭 TLS 验证解决接入问题。

| 入口 | 采用条件 | 验证重点 |
| --- | --- | --- |
| Chat Completions | 通用业务与 SDK | roles、工具、流式和结构化结果 |
| Responses | 客户端要求 | 事件、状态引用、工具结果和资源生命周期 |
| Anthropic Messages | 客户端要求 | 内容块、工具循环、签名和扩展头 |
| Gemini 原生接口 | 客户端要求 | 原生结构、工具和多轮签名 |
| Embeddings 与 Rerank | 检索场景 | 维度、分数、截断和批量 |
| 原生透传 | 不能无损转换的能力 | 路径白名单、鉴权、大小与数据治理 |

LiteLLM 官方端点目录列出多协议与透传路线，可作为候选入口，不代表全部模型功能通过验证。[端点目录](https://docs.litellm.ai/docs/supported_endpoints)

## 转换规则

原生支持保持语义；转换支持记录映射版本；部分支持声明限制并在严格模式拒绝有损请求；不支持明确报错；未验证仅进入受控试验。

同名参数不保证同义。默认值、取值范围、Token 上限、Schema 子集和工具强制选择均需测试。扩展字段通过命名空间及白名单保留，不能覆盖认证、租户和路由配置。

## 自部署维度

记录权重 revision、量化、tokenizer、聊天模板、工具解析器、推理解析器、引擎版本和启动配置摘要。分别验证模型生成工具格式、引擎解析、网关转发和客户端完成下一轮。

vLLM 和 SGLang 提供兼容接口，但接口存在不保证每个模型具备相同能力。[vLLM](https://docs.vllm.ai/en/latest/serving/online_serving/)、[SGLang](https://docs.sglang.io/docs/basic_usage/openai_api_completions)

## 流式与状态

验证事件顺序、UTF-8 分片、工具参数增量、最终 usage、结束原因和中途错误。已输出内容后默认不换模型重试；HTTP 200 不代表流成功。

文件 ID、响应 ID、会话 ID 绑定上游和项目；查询、删除及后续生成都做授权与路由亲和性。opaque 签名和加密状态不得随意裁剪、重排或转成普通文本。

兼容性最小粒度为客户端版本 × 入口协议 × 网关版本 × 上游部署 × 模型配置 × 功能。使用[矩阵模板](../templates/compatibility-matrix.csv)，普通聊天通过不能代替工具或结构化输出测试。
