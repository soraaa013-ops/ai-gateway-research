# 实施路线与责任

按退出条件推进；人员和基础设施未知时不承诺具体工期。

| 阶段 | 交付 | 退出条件 | 责任角色 |
| --- | --- | --- | --- |
| 盘点 | 上游、客户端、组织约束 | 两类真实上游与关键协议明确 | 平台、MaaS 与研发代表 |
| 验证 | 两个固定版本候选的 POC | 硬门槛通过，差距与理由明确 | 网关开发与测试 |
| 试点 | Key、目录、调试、限额和日志 | 开发者能独立接入与排障 | 平台与研发代表 |
| 扩大 | 企业身份、回归、高可用和恢复 | 升级可回滚，配额一致，值班明确 | 平台与基础设施 |
| 优化 | 增加协议、路由和成本策略 | 每项策略有评估及回归 | 产品与平台 |

## 待确认事项

MaaS 协议、认证和配额范围；自部署引擎与模型配置；实际 SDK 和开发工具；网络、私有 CA 与外部控制面限制；并发及上下文分布；身份、日志与密钥系统；计费和分摊要求。

这些信息内部盘点，不要求上传公开仓库。

## 首批工作项

1. 填写盘点表，选择关键客户端和验收目标。
2. 固定候选版本，验证 MaaS 认证与直连基线。
3. 完成适用硬门槛测试。
4. 记录选型及适配器、门户、观测集成工作量。
5. 小范围试点，采集接入耗时、排障耗时、失败分类和资源利用。

模型、引擎、模板、适配器或网关升级后重跑受影响用例。新增权重也可能改变工具输出，不能仅做 HTTP 存活检查。
